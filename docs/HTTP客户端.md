# HTTP客户端

文档类型：运行库组件使用说明。核对日期：2026-10-19。依据：组件公开接口、Android 实现、运行库清单及主机回归。适用范围：包含 `simple.runtime.components.HTTP客户端` 的运行库版本；清单提供提示信息，实际编译仍需要对应的运行库 JAR。

`HTTP客户端` 是非可视组件，支持异步 HTTP/HTTPS 请求、普通表单、原始文件及单文件 multipart 表单。配置、发送和取消在主线程调用，传输和文件读取在后台执行，事件回到主线程。已有的同步 `HTTP请求` 对象继续适用于应用自行安排的工作线程。

## 基本用法

在窗口设计器中添加一个 `HTTP客户端`，命名为 `HTTP客户端1`，再添加一个 `标签`，命名为 `结果`：

```simple
事件 主窗口.初始化()
	如果 HTTP客户端1.发送请求("https://example.com/") = 假 则
		结果.文本 = HTTP客户端1.错误信息
	结束 如果
结束 事件

事件 HTTP客户端1.请求完成(状态码 为 整数型)
	结果.文本 = "HTTP " & 状态码 & "\n" & HTTP客户端1.响应文本
结束 事件

事件 HTTP客户端1.请求失败(信息 为 文本型)
	结果.文本 = 信息
结束 事件

事件 HTTP客户端1.请求取消()
	结果.文本 = "请求已取消。"
结束 事件
```

`发送请求` 返回真只表示受理成功。网络、文件读取或响应超限等错误随后通过事件通知；忙碌、无效网址或 GET 配置正文等受理错误返回假，原因在 `错误信息`，不触发终止事件。

同一实例同时处理一个请求，直到主线程处理终止通知。在完成、失败、取消事件发出前已恢复空闲，可以直接在事件中发送下一请求。需要同时传输多个请求时使用多个组件实例。

## 提交正文

| 内容 | 设置方法 | 说明 |
| --- | --- | --- |
| 文本 | `置提交文本(文本)` | UTF-8，`text/plain` |
| JSON 等文本 | `置提交文本(文本, "application/json")` | 类型不带字符集参数，组件添加 UTF-8 |
| 字节集 | `置提交数据(数据)` | 复制数组，`application/octet-stream` |
| 普通表单 | `置提交表单(字段)` | 哈希表，UTF-8 的 `application/x-www-form-urlencoded` |
| 原始文件 | `置提交文件(地址)` | 将文件流作为整个请求正文 |
| 文件表单 | `置提交文件表单("file", 地址)` | 一个文件，字段名由服务端接口决定 |
| 文件及字段 | `置提交文件表单("file", 地址, 字段)` | 一个文件及哈希表中的附加文本字段 |

先设置正文，再调用 `发送请求("POST", 网址)` 或 `发送请求("PUT", 网址)`。支持 GET、POST、PUT、DELETE、HEAD、OPTIONS；GET 和 HEAD 不接受正文。

正文设置方法相互替换，不会叠加。正文仅供下一次成功受理的请求使用，受理后清空待提交配置；受理失败则保留。`清空提交内容()` 可主动移除待提交正文。在请求期间配置的新正文供下一次请求使用，不影响正在发送的快照。

文件地址可以是绝对路径、应用内部文件目录下的相对路径，或已获得读取权限的 `content://` URI。可直接使用 `文件选择器.文件选择完毕` 返回的 URI，无需查找真实磁盘路径。组件不申请外部存储权限，不替应用获取或延长 URI 授权。文件名和 MIME 类型从文件或提供方查询，缺失时采用通用类型。

文件按流读取，组件不把整个文件读入内存。已知且不超过整数范围的正文采用固定长度；未知或超大正文采用 HTTP 分块传输，需要服务端支持。文件表单进度包含字段、边界和文件内容；目前每个请求最多一个文件。

## 配置与结果

| 属性或方法 | 默认值或行为 |
| --- | --- |
| `连接超时` | 10000 毫秒，0 表示无限等待 |
| `读入超时` | 30000 毫秒，0 表示无限等待；不是写入或整体请求超时 |
| `响应大小上限` | 8388608 字节，仅限制响应正文，不限制上传文件大小 |
| `置请求头(名称, 值)` | 同名头不区分大小写替换，持续作用于后续请求 |
| `清空请求头()` | 清除后续请求的自定义头 |
| `正在请求` | 包含传输与等待终止通知阶段 |
| `响应代码`、`响应文本`、`响应数据` | 最近终止任务的结果；响应数据返回副本 |
| `取响应头(名称)` | 不区分大小写，同名多值以逗号及空格连接 |
| `错误信息` | 最近受理错误、传输失败或取消说明 |

请求受理时保存配置快照，之后修改头、正文和超时不会改变当前任务。`Content-Type`、`Content-Length`、`Transfer-Encoding` 由提交正文管理，不能通过 `置请求头` 设置。

响应正文完整接收后才通知完成。201、204、3xx、4xx、5xx 都是 HTTP 响应，应在完成事件中根据状态码判断业务结果。组件不自动跟随重定向，也不自动重试；应用可以读取 `Location` 并决定下一步。

响应文本按 `Content-Type` 的字符集解码，缺失或不支持时使用 UTF-8。响应缓存受大小上限限制，但解码文本及读取字节副本仍会额外占用内存，不能把该值当作组件总内存预算。发送下一请求时保留旧响应，直到新的终止通知替换；失败和取消会清空响应结果。

## 进度、取消与销毁

`发送进度(已发送, 总长度)` 和 `接收进度(已接收, 总长度)` 使用长整数，通常每 200 毫秒通知。总长度未知时为 -1；进度表示本机读写字节，不代表服务器已经完成业务处理。

`取消请求()` 返回真表示本次取消赢得终止状态，随后通知一次 `请求取消`；返回假表示无任务或任务已确定结束。完成、失败与取消最多选择其中一个通知。取消不会在界面线程等待网络关闭，也不能撤回服务器已收到的数据；提供方阻塞读取或网络关闭不保证立即结束。

调用 `销毁()` 后停止接收该组件的事件，取消剩余任务并移除宿主监听。宿主 Activity 销毁时也执行清理。应用进入后台或切换 Simple 窗口不会自动取消任务；组件拥有者应根据业务决定是否显式销毁，销毁后不能再次配置或发送。

HTTPS 使用 Android 平台的证书与主机名校验。组件没有放宽证书校验、自动重试、断点续传、写入超时或后台服务保活功能。下载大文件应使用适合文件落盘的下载组件。
