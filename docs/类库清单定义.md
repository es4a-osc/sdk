# 类库清单定义

清单告诉 ES4A“类库里有什么，以及如何显示和编辑”。它用于类库树、代码提示、成员说明和窗口设计器；实际功能仍由 Java 实现及 Simple 注解决定。

扩展库在根目录维护 `library.json`。先实现 Java API，再按本篇填写清单；API 有改动时同步更新，不能只修改版本号。编写 Java 的方法见 [Simple 类库开发](Simple类库开发.md)。

## 最小类库示例

下面的清单描述一个已经实现的“演示按钮”，公开“标题”属性和“被单击”事件。保存为类库根目录的 `library.json`：

```json
{
	"name": "演示扩展库",
	"description": "演示对象和组件的类库",
	"version": "0.1.0",
	"authors": [
		{
			"name": "示例作者",
			"email": "author@example.com"
		}
	],
	"kind": "library",
	"categories": [
		{
			"name": "扩展可视组件",
			"definitions": [
				{
					"name": "演示按钮",
					"description": "可以响应单击事件的按钮。",
					"kind": "component",
					"type": "com.example.demo.演示按钮",
					"inherits": [
						"simple.runtime.components.可视组件"
					],
					"properties": [
						{
							"name": "标题",
							"type": "文本型",
							"description": "按钮显示的文本",
							"initializer": "\"\"",
							"projection": "text"
						}
					],
					"events": [
						{
							"name": "被单击",
							"description": "按钮被单击时触发"
						}
					]
				}
			]
		}
	]
}
```

加载后，“扩展可视组件”分类下会出现“演示按钮”；设计器可编辑标题，并把它显示为组件文本。对应 Java 接口和实现见 [Android 组件](Simple类库开发.md#android-组件)。

下面按“清单 → 分类 → 类型 → 成员”的顺序说明字段。清单中的名称、类型和成员要与 Java API 对上，JSON 本身不会生成实现。

## 通用清单结构

最外层填写类库信息，`categories` 中保存分类：

| 字段 | 填什么 | 是否必填 |
| --- | --- | --- |
| `name` | 类库显示名称 | 是 |
| `kind` | 扩展库填 `library` | 是 |
| `categories` | 分类数组 | 是 |
| `description` | 简短用途说明 | 否 |
| `version` | 版本文字 | 否 |
| `authors` | 作者数组，每项的 `name` 必填，`email` 可选 | 否 |

编译器、运行库共用这套结构，通过 `kind` 区分：

| 清单 | `kind` |
| --- | --- |
| `SimpleCompiler.json` | `compiler` |
| `SimpleAndroidRuntime.json` | `runtime` |
| `library.json` | `library` |

## 分类与定义

分类用来组织类库树，包含必填的 `name` 和 `definitions`，可选的 `description`。`definitions` 中每一项描述一个对象、接口、组件或布局。

| 定义字段 | 填什么 |
| --- | --- |
| `name` | 必填，Simple 中的定义名称 |
| `description` | 这项定义的用途 |
| `kind` | 普通对象填 `object`，接口填 `interface`，组件填 `component`，窗口根填 `component.window`，布局填 `layout` |
| `type` | 对应 Java 类或接口的完整名称 |
| `inherits` | 直接父类型标识数组；Java API 使用完整类型名 |
| `icon` | SVG 图标路径，见 [组件图标](#组件图标) |
| `constants` | 常量数组 |
| `variables` | 变量数组 |
| `properties` | 属性数组 |
| `functions` | 函数和过程数组 |
| `events` | 事件数组 |
| `projection` | 容器或布局如何在设计器中排列，见 [容器的固定投影](#容器的固定投影) |
| `hover` | 设为 `true` 时，允许通常不显示说明的标点定义显示悬停说明 |

`name` 必填，其余字段按定义用途填写。组件的 `type` 使用公开接口或组件类，不填 `Impl` 实现类。

`categories[*].hidden: true` 隐藏整个分类，但其中定义仍参与代码提示和设计器候选。单个定义上的 `hidden` 无效。

分类及定义按数组顺序显示。设计器会合并含可实例化组件的同名分类，保留首次位置并按名称去重；窗口根不作为可拖入的子组件。

### 组件图标

在定义中填写 `"icon": "icons/demo.svg"`，并把对应 SVG 放在清单旁的 `icons/` 中。下面是一个方框图标：

```svg
<svg xmlns="http://www.w3.org/2000/svg" width="24" height="24"
	viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"
	stroke-linecap="round" stroke-linejoin="round">
	<rect x="4" y="4" width="16" height="16" rx="3" />
</svg>
```

图标可省略；填写后必须提供文件。推荐 [Tabler Icons](https://tabler.io/icons) 描边 SVG，统一使用 `24×24`、`viewBox="0 0 24 24"`、`currentColor` 和 `2px` 描边，并保留所用图标的许可证要求。

## 成员与参数

成员写入类型的 `functions`、`properties` 等对应数组。下面是一个静态函数条目，放在 `functions` 中：

```json
{
	"name": "取长度",
	"static": true,
	"return": "整数型",
	"params": [
		{
			"name": "文本",
			"type": "文本型"
		}
	]
}
```

它告诉 IDE：通过类型调用“取长度”，接收一个文本参数，返回整数。Java 方法也必须声明为 `static`，且签名一致。

| 成员字段 | 作用 |
| --- | --- |
| `name` | 必填，成员名称 |
| `description` | 用途、参数含义和必要条件 |
| `type` | 属性、变量或常量的数据类型 |
| `value` | 常量值 |
| `static` | `true` 表示类型成员，须与 Java 一致；未设置时不标为静态 |
| `global` | `true` 时加入全局候选，不改变编译器的名称解析规则 |
| `params` | 按调用顺序填写的参数数组 |
| `return` | 函数返回类型；过程不填写 |
| `writable` | `false` 表示只读属性 |
| `initializer` | 属性未赋值时显示的缺省表达式，见下节 |
| `editor` | 属性使用哪种输入框或选择器 |
| `select` | 属性的候选值及是否允许自定义输入 |
| `group` | 属性显示在哪个自定义分组 |
| `layouts` | 父容器采用哪些布局时，才显示该属性 |
| `projection` | 设计器如何理解这个属性，例如把它当成文本或宽度 |

参数的 `name` 必填，面向用户使用中文；`type`、`description` 可选。传址参数设置 `byRef: true`，否则按传值处理。也可使用 `passing: "传值"` 或 `passing: "传址"`，不要与 `byRef` 冲突。

只有获取器的属性写 `writable: false`；只有设置器时，在说明中写清不可读取，当前没有可用的 `readable` 限制字段。

同名函数按参数个数区分，不按参数类型区分同参数个数的重载。IDE 合并继承成员时，同名同参数个数的函数使用更具体的定义，其他成员按名称覆盖。

## 缺省值与候选值

`initializer` 表示属性没有显式赋值时，IDE 显示和分析使用的值；`select` 提供可选项。下面让“宽度”默认显示“匹配父级”，同时允许选择“适应内容”或自行输入：

```json
{
	"name": "宽度",
	"type": "变体型",
	"editor": "simple.pixel",
	"initializer": {
		"label": "匹配父级",
		"value": "长度_匹配父级"
	},
	"select": {
		"input": true,
		"options": [
			{
				"label": "适应内容",
				"value": "长度_适应内容"
			},
			{
				"label": "匹配父级",
				"value": "长度_匹配父级"
			}
		]
	}
}
```

| 写法 | 效果 |
| --- | --- |
| `label` | 用户看到的文字 |
| `value` | 对应的 Simple 表达式 |
| `select.input: true` | 可以输入候选项以外的值，输入仍由编辑器校验 |
| 省略 `select.input` 或设为 `false` | 只能选择候选项 |
| 清除属性的显式赋值 | 重新显示 `initializer`；未声明缺省值则保持未设置 |

`initializer` 和 `select.options` 中的项都可简写为非空字符串，表示显示文字与表达式相同；`select.options` 必须是数组。已有值不在候选项中时，保留原值，不自动改写。

JSON 的 `initializer` 不会自动写入单元属性区，也不负责运行时初始化。实际初值由 Java 设置器的 `@SimpleProperty` 提供，两处应保持相同默认状态；Java 逻辑初值用 `True`、`False`，清单用 `真`、`假`。对照示例见 [属性](Simple类库开发.md#属性)。

## 属性编辑器

`editor` 决定用户怎样输入属性值，不改变属性在 Android 上的行为：

| 标识 | 输入方式 |
| --- | --- |
| `simple.boolean` | 选择逻辑值；逻辑型默认使用 |
| `simple.integer` | 输入整数；整数类类型默认使用 |
| `simple.color` | 选择颜色并预览 |
| `simple.pixel` | 输入尺寸或边距，支持整数及 `px`、`dp`、`dip`、`sp` |
| `simple.layout` | 选择容器布局 |
| `simple.anchor` | 从同一父容器的其他可视组件中选目标，写入 `组件名.标识` |
| `simple.single`、`simple.string`、`simple.asset` | 普通输入框 |

`simple.anchor` 不允许选择自身。目标改名时引用随之更新；删除或移出同级容器时清理失效引用，移动子树内部仍有效的引用保留。

## 属性输入

属性值最终保存为 Simple 表达式。编辑器会检查直接值，正式合法性仍由编译器判断：

- 尺寸整数按数值保存，`30dp` 等单位文本保存为字符串表达式，`30dx` 等错误单位拒绝提交。
- 数值输入按对应整数或浮点类型校验；普通文本转为字符串字面量，已有字符串或表达式保留原意，变体型按输入外形处理。
- 单独符号、调用和资源引用由 SDK、项目索引核对；带运算符的组合表达式不在属性框内递归验证。

## 分组与适用布局

这一节只控制**属性框中怎么显示属性**：`group` 设置分组名称，`layouts` 设置显示条件。

例如，“位于左边”需要根据另一个组件确定位置，只在相对布局中有意义。下面把它放入“相对组件”分组，并限定父容器采用相对布局时才显示：

```json
{
	"name": "位于左边",
	"type": "整数型",
	"editor": "simple.anchor",
	"layouts": [
		"布局_相对"
	],
	"group": "相对组件"
}
```

在这个场景中：

| 字段 | 用户会看到什么 |
| --- | --- |
| `layouts: ["布局_相对"]` | 直接父容器是相对布局时显示该属性，其他布局下隐藏 |
| `group: "相对组件"` | 属性放在父级布局分组下的“相对组件”自定义组 |
| `editor: "simple.anchor"` | 用户可选择一个兄弟组件作为位置参照 |

`layouts` 可列出多个 SDK 布局常量，不写时不按父布局限制显示；写了就必须是非空字符串数组。窗口根没有父容器。`group` 可独立使用，填写非空名称即可。

判断父布局时先看其显式赋值，未赋值则看布局属性的 `initializer`。切换布局只改变属性是否显示，已有的不适用赋值仍保留。

`layouts` 不设置容器布局；容器在画布上如何排列，由下面的投影配置说明。

## 容器的固定投影

设计器显示的是简化画布，不执行 Android 界面代码。`projection` 告诉它怎样显示组件：

| 写在哪里 | 写法 | 作用 |
| --- | --- | --- |
| 组件或布局定义上 | 对象，如 `{"layout": "frame"}` | 确定子组件排列、滚动方向或数量限制 |
| 属性条目上 | 字符串，如 `"text"` | 告诉画布这个属性表示文本、宽度等，见 [设计器投影](#设计器投影) |

固定排列的容器可在自己的定义中写：

```json
{
	"layout": "frame",
	"scroll": "vertical",
	"limit": 1
}
```

这是 `projection` 对象的内容，表示子组件重叠排列、设计期可纵向浏览、最多直接放一个可视子组件。它只描述容器已有的能力，不会让普通组件变成容器。

| 字段 | 填什么 | 省略时 |
| --- | --- | --- |
| `layout` | `absolute` 绝对、`frame` 单帧、`grid` 表格、`linearHorizontal` 水平线性、`linearVertical` 垂直线性、`relative` 相对布局 | 没有可用真实布局值时使用单帧布局 |
| `scroll` | `none`、`horizontal`、`vertical`，表示设计期内容浏览方向 | 没有固定滚动声明 |
| `limit` | 非负安全整数，限制直接可视子组件个数，非可视组件不计数 | 不限制个数 |
| `value` | 仅布局定义使用，填写对应的布局选择值，必须同时声明 `layout` | 不建立布局选择值与定义的关联 |

容器身份由 `component.window` 或 `组件容器` 继承关系决定；固定投影不会新增可编辑的布局属性。组件存在有效的真实布局属性值或缺省值时，优先使用真实布局，属性名通过投影识别，不要求叫“布局”。

### 可切换布局的关联

当 Simple 中选择 `面板.布局 = 布局_线性` 时，设计器需要知道该选择对应哪份布局定义。在线性布局定义中声明：

```json
{
	"name": "线性布局",
	"kind": "layout",
	"projection": {
		"layout": "linearVertical",
		"value": "布局_线性"
	}
}
```

其中，`value` 对应“选中了什么”，`layout` 对应“画布怎么排列”。`value` 必须是非空的常量引用或数值表达式，仅用于 `kind: "layout"`。

画布和属性框按解析后的值查找布局定义，不按中文名称猜测。线性布局方向读取该定义中投影为 `orientation` 的属性，未提供方向时使用声明的方向。选择值未知、关联缺失或同值布局不唯一时，不猜测排列，画布相关布局操作保持只读。

固定布局按加载顺序选用首个对应布局定义，以判断子组件属性是否适用。长度、方向、颜色和对齐可以解析确定的清单常量，不执行其他表达式；画布回写对齐或适应内容长度时，优先使用属性中的同值候选，缺少候选则写语义数值。

## 设计器投影

属性的 `projection` 说明“把这个属性当什么用”。例如“标题”属性写 `"projection": "text"` 后，画布用它显示组件文本；改中文属性名不会改变这层含义。

画布读取属性区中的显式值，没有时读取清单缺省值。继承属性同样有效，同一投影以更具体的属性为准。标识区分大小写；不写或写入未知的属性投影时，该属性仍可编辑，但不参与画布显示。

### 标识、尺寸和位置

| 标识 | 作用 |
| --- | --- |
| `id` | 相对布局引用的组件标识，不是组件名称 |
| `width` | 宽度，支持适应内容、匹配父级和固定 DIP；拖动调整时写回该属性 |
| `height` | 高度，规则同宽度 |
| `x` | 绝对布局中的左边位置，移动时写回该属性 |
| `y` | 绝对布局中的顶边位置，移动时写回该属性 |

### 外边距和内边距

| 标识 | 作用 |
| --- | --- |
| `leftMargin`、`topMargin`、`rightMargin`、`bottomMargin` | 左、上、右、下外边距，控制与外部的间隔 |
| `paddingLeft`、`paddingTop`、`paddingRight`、`paddingBottom` | 左、上、右、下内边距，控制边界与自身内容的间隔 |

### 文本显示

| 标识 | 作用 |
| --- | --- |
| `text`、`hint` | 主文本及提示文本，主文本为空时显示提示 |
| `textColor`、`hintTextColor` | 主文本及提示文本颜色 |
| `textSize`、`fontFamily` | 字号与字体，支持默认、无衬线、衬线或等宽字体 |
| `fontBold`、`fontItalic`、`singleLine` | 粗体、斜体及单行显示 |
| `backgroundColor`、`backgroundImage` | 背景颜色及图片 |

### 容器和父级布局

| 标识 | 作用 |
| --- | --- |
| `layout` | 容器排列子组件所用的布局 |
| `orientation` | 线性布局的水平或垂直方向 |
| `gravity` | 自身内容的对齐；用于布局定义时表示子组件整体对齐 |
| `layoutGravity` | 当前组件在父容器分配空间内的对齐 |
| `weight` | 当前组件分配线性布局剩余空间的权重 |
| `weightSum` | 线性容器计算权重时使用的总值 |
| `baselineAligned` | 基线对齐 |
| `rowCount`、`columnCount`、`row`、`column` | 表格行列数及组件所在单元 |
| `shrinkAllColumns`、`stretchAllColumns` | 表格列宽收缩、拉伸 |
| `scrollable`、`scrollbarEnabled` | 运行时滚动与滚动条属性的语义标记，不控制设计器导航 |

相对布局还支持以下位置关系：

| 关系 | 标识 |
| --- | --- |
| 位于兄弟组件的某一侧 | `leftOf`、`above`、`rightOf`、`below`、`startOf`、`endOf` |
| 与兄弟组件对齐 | `alignBaseline`、`alignLeft`、`alignTop`、`alignRight`、`alignBottom`、`alignStart`、`alignEnd` |
| 与父容器边缘对齐 | `alignParentLeft`、`alignParentTop`、`alignParentRight`、`alignParentBottom`、`alignParentStart`、`alignParentEnd` |
| 在父容器中居中 | `centerInParent`、`centerHorizontal`、`centerVertical` |

窗口内容溢出时可横纵浏览，嵌套容器按定义级 `projection.scroll` 浏览。设计期滚动不写入属性区，也不受运行时滚动开关影响。属性显示条件见 [分组与适用布局](#分组与适用布局)。

## 路径与注册

图标等相对路径从清单所在目录算起。`type`、`inherits` 使用 Java 完整类型名，不是文件路径，也不使用 Simple 代码中的别名。

将构建好的类库目录放进所选 SDK 的 `libraries/`，包含 `library.json` 即会被发现，更新后执行“ES4A: 刷新类库”。首次选择 SDK 见 [准备开发环境](Simple项目开发.md#准备开发环境)。

ES4A 先加载编译器、运行库，再按目录名加载 `libraries/` 直接子目录中的清单；不扫描更深目录或其他文件名。同名定义优先使用先加载者，单个清单出错不阻断其他有效清单。

清单不能代替 JAR，也不声明依赖版本。构建安装见 [Simple 类库开发](Simple类库开发.md#安装与接入-sdk)，版本选择见 [依赖版本与冲突](Simple类库开发.md#依赖版本与冲突)。

## 定义和检查边界

名称及 `group` 使用非空字符串，字段类型按本文填写。`type`、继承关系、参数和返回值必须与 Java 实现一致；未知字段不会自动产生新功能。定义级投影填写无效值会报加载错误，子组件数量限制也应符合容器实际能力。

### 修改后的验证

1. 检查 JSON、图标路径及必填字段。
2. 刷新类库，检查分类、补全、悬停、参数和继承成员。
3. 涉及属性或投影时，检查设计器中的编辑、排列、尺寸、文本及滚动。
4. 修改了公开 API 时，同步 Java 注解、重建类库，再用 Simple 项目编译并到设备上验证。

清单加载成功只说明 IDE 能读取；设计器是简化显示，不能代替 Android 设备验证。仅修改显示信息不会改变运行功能。
